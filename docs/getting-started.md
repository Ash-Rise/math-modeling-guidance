# 第一次使用

你只需要提供题目、目标和截止时间。AI 负责维护文件和本地版本；遇到会影响题意或结论的重要选择，再向你解释并询问。

## 1. 打开工作区

在仓库首页点击绿色 **Code → Download ZIP**，解压到独立文件夹。在支持文件读写和终端命令的 AI 编程环境中打开它，确认根目录能看到 `AGENTS.md`。不要只把网页链接发给一个无法操作文件的聊天窗口。

让 AI 先检查 Git 和 Python。示例使用 Python 3.11—3.13，不需要安装根目录 `requirements.txt`。已有数学建模 Skill 可以用于真实任务；先体验小示例无需额外配置。

如果你习惯终端，也可以：

```shell
git clone https://github.com/Ash-Rise/math-modeling-guidance.git
cd math-modeling-guidance
```

下载 ZIP 不含 Git 历史。AI 应先确认这个文件夹不属于其他仓库，再初始化本地 Git。初次提交若缺少姓名和邮箱，由你指定，仅配置当前仓库。Git 未安装或身份未配置时，可以先计算并保存文件，但 AI 不能声称已经建立版本检查点。

## 2. 先体验一次完整的小任务

把下面的话发给 AI：

> 请读取根目录 AGENTS.md，按 projects/quickstart-canteen/README.md 运行食堂备餐教学示例。检查环境后执行默认方案，告诉我推荐备餐量、平均损失以及这份结果的适用范围。保存输入、代码和输出到本地检查点，不推送远端。不要替我编造 Git 提交身份。

运行完成后，打开示例项目里的 `results/baseline/report.md`。你应能看到推荐量、少量对照和局限；同目录的 `summary.json` 保存参数与数值，`candidates.csv` 保存完整候选比较。具体预期结果见 [示例说明](../projects/quickstart-canteen/README.md)。

这些文件由计算脚本生成，不是 AI 凭空填写。示例只有合成数据，练习的是操作流程，不证明真实预测效果。

## 3. 换成自己的题目

在 `projects/` 下新建一个任务文件夹，例如 `my-project/input/`，放入原始题面和附件。告诉 AI：

> 请读取 AGENTS.md，题目和附件在 projects/my-project/input。我的目标是……，截止时间是……（含时区），需要交付……。先核对输入是否完整，解释每问需要回答什么，再完成可检查的基础方案。常规技术工作自主推进；重要假设先给出分析和建议。请维护本地版本，阶段结束时告诉我进度、结果位置和下一步。

开始不需要自行创建 `decisions.md`、`state.md`、测试目录或论文模板。AI 按实际需要建立；不要把小示例的成本模型和假设照搬到你的题目。

模型解释、数据缺失和计算能力问题应分别说明。只有需要你补充信息或决定实质取舍时才暂停相关工作，其他可推进部分继续。

## 4. 暂停和继续

离开前说：

> 保存当前文件，记录当前做到哪里、还有什么没解决、下一步是什么，并创建本地检查点。告诉我哪些文件已保存、提交是否成功。

新对话仍打开同一个文件夹，然后说：

> 请读取 AGENTS.md，从 projects/my-project 的原题、决策、状态和结果恢复任务，继续下一步。不要重新做已经完成且仍然有效的计算。

先保存并核对恢复信息，再切换对话；不必为了形式每个小步骤都换对话。Git 保存文件历史，不保存未写入文件的聊天内容。删除文件夹也会丢失其中的本地历史，异地备份需另行同步。

## 5. 常见卡点

| 遇到什么 | 怎么处理 |
|---|---|
| AI 只能描述步骤，无法运行 | 使用具备项目文件和终端权限的环境，或自己执行示例 README 的命令 |
| 找不到 Python 或 Git | 让 AI 说明缺少哪一项和适合当前系统的安装步骤；安装后重新检查 |
| 文件保存了，但没有提交 | 检查 Git 是否初始化、提交身份是否配置，以及文件是否被忽略 |
| Excel、PDF 没进入提交 | 当前忽略规则可能排除它们；让 AI 核对需备份的文件，再按项目添加例外 |
| 提交成功，GitHub 上没有变化 | 本地提交不等于推送；先确认自己的远端仓库、权限和要同步的内容 |
| 两个人同时改同一问 | 明确负责人和整合人，先比较各自假设与结果，再合并 |

需要远端同步、多人分支协作或理解文件职责时，再看 [进阶工作流](workflow-details.md)。方法和规则由 AI 按需读取，你不必先通读它们。

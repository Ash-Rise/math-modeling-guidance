# 科研图：从主张到可核查视图

本页是 playbook §6 的实现参考，不增加交付物或验收关卡。使用项目解释器；基础依赖为 Matplotlib、PyYAML，真实数据回归示例另用项目已有的 NumPy、pandas、Pillow。调色、样式与布局不能修复来源错误、不可比实验或过强结论。

## 先判断必要性，再建立视觉方向

从当前正文的一条主张和真实结果开始，说明图要让读者直接看见哪种关系。多面板各自承担不同一步解释；遮住某个面板后若没有损失有效信息，优先合并或删除。保留有用的图表互补，不把“用了新图型”当作信息增量。

选模板之前，先回答“读者要比较什么、需要哪些共同条件、图比已有文字或表格减少了哪一步心算或查找”。若只是再显示几个总额、两个孤立数值或一句话能交代的高低关系，通常引用已有文字/表格；若能显露汇合分流、局部失配、非线性响应、分布形状或难以跨表重建的关系，则有保留价值。几百个格子不自动比两条曲线更有信息，不能用固定点数或图数代替判断。

多面板合并取决于读者是否需要对照它们，而非它们属于同一小节。先画承载核心关系的最小视图，再决定辅助面板；若撤下面板后主张仍同样容易理解，就不为填满版面保留它。判断留在已有工作说明或必要的代码注释中，不另建逐图合同、评分表或审批流程。选图决策树只缩小候选，不能替代正文任务判断（参考 [Data to Viz](https://www.data-to-viz.com/index.html)）。

数模选图优先对应题目要求读者核查的对象：物理/几何关系如何进入约束、方案怎样执行、关键条件改变时决策如何变化、验证暴露了什么局限。机制图应显露非显然关系，例如同条件下某种结构为何造成遮挡或违约、调整后怎样消除；不把问题分析改成几个顺序框就算补足证据。不按章节字数、图型数量或留白面积自动补图，也不因原图已经存在而保留错误的图型。国奖案例用于学习这些表达关系，不以奖项担保每张图的美感或正确性。

外部优化提示词中的单位、标注、可复现要求可复用，统计修饰须另有证据：确定性优化结果不自动添加 SD、SEM、置信区间或显著性星号；敏感性范围保留其条件含义。可以从本项目正式结果派生正文尚未展示的关系，但不能用估计值、合成数据或缺失的迭代历史补齐漂亮模板。固定线宽、点数阈值、期刊版宽和粗体标题均不能覆盖项目已认可的视觉方向。

当用户要求借鉴案例，或现有风格确实不合适时，选择两三张与当前任务相近的实际成图。打开图片查看，不能只读 skill 的介绍或以仓库名称、星数、期刊名判断质量。比较字体层级、轴线与数据的视觉重量、颜色角色、标签位置、面板比例和空白；说清借鉴哪几项。先区分借用风格、借用布局与复用统计实现：数据含义不匹配时只借风格，不引入模板的归一化、平滑、聚合、误差棒或结论。图库里的合成数据和示意图不能进入正式证据。

先用真实数据完成一至两张代表图，例如密集时序和比较图，按论文插入宽度打开检查。解决颜色发灰或抢眼、标注凌乱、图例挤压和比例失衡后，再把共同参数保留在项目现有生图入口中，推广到其余图。由 agent 自主完成这一步，除非用户明确要求先确认；不另建审批阶段、风格合同或截图档案。完整生成后仍逐张看图，不能用一张代表图替代最终检查。

优先纯色填充、清晰轮廓和少量关键标注；不自动加点、斜线纹理、渐变或阴影。冗余识别可以来自直接标签、固定分组顺序和面板位置。只有测量点、事件或线型确实有含义时才显式使用相应标记；用户明确禁用的装饰不因通用 skill 的建议而恢复。

关联对照优先于增加图种：在共同条件、坐标或时间轴下，把模型输出与可执行方案、拟合与残差、预测更新与决策修订对应起来，让读者直接核查差异落在哪里。辅助视图只保留主张所需的残差、局部或边界，不机械补齐诊断套件。实例选择说明规则与适用范围，不挑效果最好的一例代表总体；预测与决策同时变化也不能据此分离各因素的因果贡献。

## 选择视图与颜色

先确定读者需要核查的关系；以下是选择依据，不是每题必画清单。

| 要让读者看见什么 | 候选视图与编码 | 不能由图推出什么 |
|---|---|---|
| 离散对象的大小、排名 | 点图/横条；类别色或重点色；长名称留在纵轴 | 排名不等于差异有统计意义；柱长比较保留零基线 |
| 二维参数组合的响应 | 热图；连续值用顺序色带，标单位和范围；小矩阵可标数值 | 格点间不擅自插值；调参集最低格不代表泛化或全局最优 |
| 相对基准的正负偏离 | 差值点图或发散热图；显式零线/有意义中心；统一比较范围 | 不能把数据中点自动当零；两侧颜色转灰度后通常无法区分符号 |
| 事件时序、可行时间窗 | timeline/区间与实际事件点分层；颜色配形状、标签 | 可行窗口不是置信区间；合并区间不能掩盖短缺口 |
| 估计与不确定性 | 点区间、小多图或曲线带；CI、PI、SD、分位数分别写清 | 条件敏感性范围不是统计 CI；均值 CI 不是个体预测区间 |
| 参数响应、条件敏感性 | 连续参数用响应线；离散假设用点图，不连成连续曲线；标基准 | 说明固定量、改变量、是否重新拟合；不同频段/样本不能直接按误差排名 |
| 机制、方案形成 | 与公式对应的示意图、分量对照、候选点图 | 示意尺寸不当实测值；候选终点不伪装迭代历史；条件派生不是独立验证 |
| 空间几何、路线 | 等比例坐标、方向箭头、遮挡关系；必要时整体加局部 | 投影不是三维充分性证明；网络布局距离不自动是地理距离 |

`shared.figure_style.PALETTES` 是小型语义入口：categorical 用用户选定的 Paul Tol Bright 原始七色（蓝、红、绿、黄、青、紫、灰）；sequential 用 Matplotlib `Greens`；diverging 用紫—白—绿 `PRGn`；highlight 为 Bright 蓝/参考灰。新绘或修订图不采用蓝橙对照。保留已有、已审核的项目语义配色，不为统一而换色。分类色不插值成连续色带；发散色带显式传 `TwoSlopeNorm(vmin=..., vcenter=基准, vmax=...)`，比较面板共享 norm。缺测或不适用用空白或浅灰底加文字，不画成零。周期量另选 cyclic 色带。

Bright 的来源标注为 color-blind safe，但这不保证任意取色、透明度、白底细线或灰度印刷都可辨。优先以直接标签、分组位置或有含义的实虚线辅助识别；大类别数先考虑分组/小多图，不无限循环颜色。顺序色带检查明度次序；发散色带的灰度通常仅保留偏离幅度，若任务需要黑白输出则改用带符号标注、等值线或分面，不能声称彩色版直接转灰就保留符号。Bright 原值不为追求柔和而任意改色后仍沿用原名称；项目自选配色另行命名。浅色优先用于面积，白底细线保持足够深度；重叠严重时调整视图，不能只继续降低透明度。

### 按关系挑模板，再核对实现

模板同时按“关系、数据结构、输出用途”匹配，不能只看图名或论文领域。打开成图与代码，检查列映射、聚合、分母、排序、尺度、平滑、截断和缺失处理。美观的示例也可能带有错误或不适用的变换；例如桑基图节点与流带必须采用同一宽度比例，不能只检查总数相等。

| 关系与用途 | 优先查找的实现 | 适用边界 |
|---|---|---|
| 时间、响应、同条件比较 | 项目 Matplotlib 入口；Wilke 小多图/复合图案例 | 比较幅度时共用尺度；异尺度明确说明，不把类别连成连续变化 |
| 有向流量的汇合、分流、损耗 | ECharts Sankey；source/target/value 数据 | 核对单位、收支、来源身份与库存变化；不能把普通总额比较伪装成流量，不因流量小而删掉关键损耗 |
| 多条件分布、配对变化 | Data to Viz 对应结构入口，再查可运行模板 | 确认样本、配对、分箱/带宽与不确定性含义；不从模板自动生成统计证据 |
| 模型结构、信息边界、分支及公式几何 | draw.io/SVG；公式与几何定位紧密时可用 TikZ | 结构确有解释作用时采用；框和箭头不是数据证据，线性步骤换成框图不自动增加价值；不为换工具迁移已认可图 |

借鉴 viz-skills 的“选图知识与模板实现分开”，但复用粒度以实际消费者为准：先保留已认可项目脚本，出现另一处真实复用需求再提炼共用部分。不批量安装图库或建立无消费者的模板注册框架；示例数据仅用于学习。采用模板时在对应脚本注明来源与适配边界，保留项目语言和已认可样式，不照搬外部 R-first、固定字号、双格式输出、自动裁值或确认关卡。

机制图先安排实体与关系，再连接明确锚点，最后放公式和标签；结构图优先相对定位，几何图按模型坐标定位。检查线是否穿过无关实体、方向是否明确、标签是否与线争位；组框随内容收拢，间距和箭头粗细按最终尺寸调整。留白用于分组，不为填空新增说明框；粗渐变箭头、深色标题条、伪三维和固定厘米间距都不是机制图的默认质量标准。

### 从配色库提炼到实际图

先分清对象关系，再挑颜色：并列对象用分类色；同一对象的观测/预测可用同色实虚线；重点与参考用一个重点色配中性灰，不给每条辅助线分配新颜色。当前七个默认分类色只是薄层容量，不是每题色数规定；超过容量可显式设计项目映射或分面，不能悄悄重复色循环。`paper_style()` 只循环颜色，默认实线且无点标记；`category_styles()` 只分配稳定的类别色。有语义的虚线或事件标记由具体绘图调用显式指定，避免调用顺序无意中改变线型。

自然感来自相近的视觉重量和明确的层级，不是整体调淡：白底数据线保持足够深度，浅色用于面积或背景，参考信息适度弱化但仍可读。先在真实图上评估最难区分的对象，而不是只看色卡。关键缺口、数值和边界的小字优先用深中性色，不能为呼应数据颜色而牺牲文字对比度。默认颜色是可覆盖起点；不要为不同章节随意换同一语义对象的颜色。

色带与文字共同设计。顺序色带不可因喜欢某组分类色而随意插值；改变色带或反转方向后，热图文字黑白色必须由实际背景明度选择，不能把“低数值用白字”写死。`contrast_text(cmap(norm(value)))` 用于不透明背景；透明填色先与底色合成。发散图仍需显式中心和符号信息，不能把紫/绿自动解释为差/好。

## 样式和布局起点

精确数值在 `personal-paper-profile.yaml` 的 `figures.matplotlib`，默认字体复用现有 typography，宽度由纸张与页边距计算。图内字体可按项目视觉方向显式覆盖；例如中文无衬线与 Arial 搭配时，先验证实际安装和数学字符，不改变正文排版字体。compact/wide/tall 只是布局起点，允许按标注和面板关系覆盖高度。compact 必须按半正文宽插入；不能按全宽作图后缩半而仍声称字号合格。

```python
from shared.figure_style import paper_style, figure_size, category_styles, save_figure
import matplotlib.pyplot as plt

styles = category_styles(["观测", "模型"])  # 只映射颜色，完整语义顺序只建一次
with paper_style():
    fig, ax = plt.subplots(figsize=figure_size("wide"), layout="constrained")
    ax.plot(x, observed, **styles["观测"], label="观测")
    ax.plot(x, predicted, **styles["模型"], linestyle="--", label="模型")
    ax.set(xlabel="时间 / s", ylabel="响应 / m")
    ax.legend()  # 能清晰放置时也可用曲线旁直接标签
    ax.grid(axis="y")  # 仅在有助读数时启用
    save_figure(fig, output_png)  # 输出格式按消费者选择；校验 DPI 等硬约束
```

在仓库根目录以模块运行入口，或由项目入口定位仓库根后导入 shared；不要依赖个人绝对路径。模块不会导入即改全局 rcParams，也不设置后端、生成数据、自动图例或导出多种格式。缺少配置字体会报错；跨机器可显式指定已安装的中英文字体，但仍检查缺字。

密集谱线通常关闭 marker，用线型与直接标签；稀疏采样才逐点标记。多面板共用的标签和图例放在独立空间，不挤在标题上；比较面板按条件对齐，异单位或不同范围显式写清。可用 `subplot_mosaic`/`GridSpec` 处理长标签与不等宽面板，不封装一套自动布局引擎。默认轻量坐标框适合结果图，空间/热图可局部恢复四边框；不强制每张图同网格、同高宽比。

## 针对实际风险的 QA

### 跨工具比较实际输出

Matplotlib、ECharts 与 SVG/流程工具输出先按同一论文插入宽度摆在一起检查。统一的是同义对象的颜色角色、文字层级、线条视觉重量和读数口径，不是所有图同尺寸、同图型。参考 [Wilke 第21章](https://clauswilke.com/dataviz/multi-panel-figures.html)的尺度与排版对照：相似的曲线幅度可能来自坐标设置，面板标号也不应压过数据。

跨后端换算有效字号：若字体在宽度为 W 的画布中占 f 个同单位长度，插入宽度为 w 英寸，则有效字号约为 `72*w*f/W` pt。浏览器的 f/W 用 CSS px，不能把加倍截图后的像素宽度与原 CSS 字号混算；截图倍率只增加采样精度。同时检查实际中文/数学字体、透明填色与白底的合成效果、裁切，以及缩小后能否辨认窄流带或缺口。

交互预览和论文静态图分别验看：悬停辅助探索，但关键单位、对象含义与支持结论的读数不能只藏在 tooltip 中。发生 SVG/PNG 转换时，重新打开实际消费文件，检查字体替换、渐变、裁切和透明背景。渲染后端、依赖与结果读取由仓库入口定位，避免个人缓存路径；已认可样式留在代码，当前反馈留在 state，README只保留入口与必要消费者说明。

沿用 §6/§7 的来源和视觉检查，不新增日志或 manifest：从现有脚本追溯数组、条件、单位和图注；检查变换是否保留来源含义。局部重绘应对比绘图对象的坐标/区间/矩阵与源值，避免“样式修改”改变数据。按最终插入宽度看清标签、线型、legend、面板顺序、缺口与重叠；同时看灰度，必要时做色觉缺陷模拟。模拟只能发现部分可辨识性风险，不能认证所有读者/设备。缺字告警、边界检查有用，但不能替代实际看图。QA 预览放临时目录，输出结论到终端/PR，不提交截图流水账。

将检查结果分开陈述：数据与导出验证回答“有没有画错、能否正确输出”；视觉检查回答“读者是否容易看清关系、整体风格是否协调”。不能以测试通过、300 DPI、无越界或色觉友好色卡宣称图已美观或获用户认可。交付展示实际成图，并说明删改如何帮助读者核查正文，而非只报生成数量。

采用外部渲染脚本前核对它实际引用的文件和依赖，不把 README 中的能力声明当成已实现功能。TikZ 编译后检查缺字日志并打开最终消费图；正则源码检查只能提示部分写法，非空 PNG 只能排除部分渲染失败，都不能证明无重叠、几何正确或图有证据价值。导出规格仍来自项目消费者，不沿用外部示例的预览 DPI 或固定交付套件。

# 数学建模与论文方法手册

> 角色：按需查阅的方法库，不是项目治理文件或强制 SOP。
> 权威边界：题目事实以原题/官方材料为准，项目已批准语义以 `decisions.md` 为准，治理边界以 `MCM_AI_Governance.md` 为准；本手册只提供方法建议。
> 使用方式：只读取当前任务相关章节，不因存在本手册就机械执行全部流程。

## 1. 题意、数据与模型设计

### 1.1 从权威输入开始

先回到原题、官方附件和原始数据。旧论文、旧代码、README、缓存结果只能作为待审材料，不能替代题面或 Accepted Decisions。

区分三类信息：

- **题目事实**：题面或官方数据明确给出；
- **建模假设**：为闭合模型而引入，必须说明影响范围；
- **未知/歧义**：现有材料无法确定，不用旧稿或实现细节填补。

题目只给出区间或情景集合而没有概率分布时，不擅自赋予概率并构造总体期望；优先报告条件结果、情景结果、阈值或边界。为闭合模型补充信息时，若选择会改变问题语义或结论含义，仍按 Governance 的决策边界处理。

开始建模前至少弄清：每个子问真正要求输出什么、变量与单位、可用数据、决策变量、硬约束、评价指标，以及哪些语义仍未确定。

把候选解释升级为 Decision Proposal 前，先按 Governance 的 Question Gate 从原题、附件、Accepted Decisions 和其他分类 authority 消歧。为了便于计算而舍弃题面信息的近似仍是近似，数学上可定义的目标也不因此成为题意选项；只有多个未被 authority 排除、且各有独立、实质、任务相关理由的解释仍无法约简时，才进入人类决策。题面没有分别明说每种闭合方式，不足以单独淘汰其中合理的一种。

### 1.2 选择最小充分模型

模型复杂度应由问题和证据需求驱动，而不是由“算法更高级”驱动。简单模型已经能回答题目时，不主动叠加多指标算法、元启发式、复杂预测器或二次优化层。

选择求解方法前，先利用守恒、容量、必选关系、可分解结构、对称性或支配关系约化问题，并评估约化后的变量数、候选数或状态空间。若小规模问题可以完整枚举，或成熟精确方法能在合理成本内求解，应优先取得精确解；只有精确求解确实不可行时，才采用启发式或元启发式方法。论文中的算法选择理由应落到本题结构与计算规模，例如变量类型、目标或约束的可分性、光滑性和搜索空间，而不是只说“算法高效”或“变量较多”。算法比较、分阶段搜索、近似筛选和分解求解只在它们解释了方案如何产生、精度与成本如何取舍，或为关键结论提供必要证据时展开；同时说明各阶段保留、近似或舍弃了什么。

枚举、求解器调用和启发式搜索属于求解方法，不能替代模型定义。即使候选集很小，也应先闭合说明决策、可行域、目标和结果指标之间的关系，再用枚举给出求解与最优性证据。

存在多个真实可行的模型族且理论上难以区分时，先比较它们对题意的匹配、假设成本、可解释性、数据需求和结论敏感性；必要时再做最小共同 pilot。不存在真实分歧时，不为了形式制造 2—3 个候选方案。

优先使用成熟稳定的数学/数值工具；只有当现有工具不匹配问题、引入依赖反而增加不透明性，或核心方法本身就是研究对象时才自行实现。

### 1.3 先解释语义，再写公式

每个核心模型应先用自然语言回答：对象是什么、决策是什么、约束是什么、目标是什么、输出如何解释。随后再给符号、公式和算法。

数值网格、离散采样点、求解器容差、随机种子等实现参数不能自动晋升为数学定义。连续变量用有限节点计算时，应明确“定义域”和“数值采样”的区别；当网格宽度、采样密度、搜索容差或截断范围可能改变可行性、最优方案或报告精度时，应以网格加密、不同分辨率对照、误差界或适合该方法的收敛证据说明结论已稳定，而不是只列出参数值。

## 2. 实验、仿真与证据

### 2.1 证据必须能改变决策或支撑主张

增加研究、参数扫描、仿真复制、敏感性分析或额外模型前，先问：新增证据可能改变哪个重要判断？最小可信实验是什么？若进一步计算大概率不会改变行动，就停止。

敏感性分析优先寻找参数阈值、结论翻转点和可行域边界，说明结论在什么条件下保持或失效；不以机械百分比扰动代替真正影响结论的边界证据。证据名称应与其实际回答的问题一致：参数响应或机制解释属于敏感性/结果分析，网格加密与容差对照支撑数值稳定性，基准算例、独立重算或样本外对照才可能支撑相应层面的正确性或外推表现；不能把任一曲线笼统称为“模型验证”。

正式大规模计算前先运行足够真实的小规模链路，确认模型含义、输入输出、统计口径和执行路径均可用。只有发现性能确实阻碍正式实验时才 profile 和优化。

分析与求解中，搜索候选、模型比较、敏感性、关键中间量或被淘汰路线若实际改变了重要判断，且很可能用于解释论文核心主张，应在产生时保留最小充分、可追溯的证据：足以恢复比较条件、关键结果及它改变了什么判断，而不只留下最终答案。论文中的模型形成、方案选择和机制解释是具体消费者；不能仅因尚未写到正文就丢弃其依据，也不因此保存全部试验流水账。能由当前模型与结果确定性恢复的量保留其计算依据即可；无法恢复的历史候选或比较应保留实际记录，不在写作时凭最终结果补造。

### 2.2 随机实验

复制次数、warm-up、采样节点和置信区间方法由问题精度与模型结构决定，不使用固定数字作为跨项目规则。

比较策略时，如随机环境允许，优先采用共同随机数或其他配对设计降低比较方差；报告时说明比较对象、样本量和不确定性口径。

长计算应在合理粒度保存有效进度，使中断后无需从零开始。具体使用批次、checkpoint、增量结果或任务队列由实现决定。

### 2.3 证据冲突处理

数值、统计口径或论文描述冲突时，按证据链向上追溯：

1. 找到最原始的观测或复制级结果，确认单位、样本量和筛选条件；
2. 写清统计量、指标或置信区间的定义；
3. 使用独立路径重算最关键结果；
4. 再与汇总表、图和论文正文逐层比较；
5. 原始证据不足时保持“未知”，不以两份派生文档相互一致作为证明。

审查结论可使用三种证据状态：

- **已验证事实**：直接回到原始数据、代码、公式、文献原文或文档实际结构核验；
- **合理推断**：证据支持但依赖明确假设；
- **未知**：材料不足，不能补成确定结论。

## 3. 编程与数值实现

优先保证实现可读、可检查、可复现，再追求抽象或性能。避免为了 DRY/SOLID 等标签提前制造抽象层；少量重复通常比错误抽象更便宜。

模块按稳定职责划分；只有当数据格式或接口确实被多个下游消费者依赖时才建立稳定 schema/contract。临时中间结果不需要统一元数据体系。对第 2.1 节确有解释用途的证据，求解输出应保留相应候选、比较或中间量及必要的输入条件、模型/结果版本和指标含义，使后续能核查选择依据，而非只输出最优值。沿用项目已有分析、结果文件或计算入口即可，不新建统一 evidence registry；只有实际需要迭代过程证据时才记录轨迹，不默认保存全部求解器日志。

优化遵循：正确的小规模链路 → profile → 优化真实瓶颈 → 复验结果一致性。不要凭直觉重写大段代码来“提速”。

自动测试优先保护稳定、重要、可机械检查的不变量，例如题目硬约束、模型定义域、守恒关系、统计分母、跨午夜状态等。一次性 bug 不自动变成永久测试；是否保留取决于该 failure class 是否稳定且后果重要。

## 4. 论文内容组织

`shared/` 下的 `references/`、`candidate-library/`、`template-review/` 及模板参考材料是按需使用的辅助资料库，作为整体不构成项目 authority。它们适合在比较论文结构、表达质量、证据展示方式或模板视觉差异时选择性查阅，不在题目分析阶段默认批量读取；其中的题目特定模型、章节安排、措辞和版式不能机械复制为当前论文或跨项目规则。若资料本身来自官方，其效力来自官方来源，而不是所在目录。

论文结构服务于证据链，不要求所有题目机械套同一目录。一个常用基线是：

```text
问题重述
问题分析
模型假设与符号
任务一：问题 → 模型 → 求解或推导 → 结果 → 验证/边界
任务二：...
任务三：...
模型评价
参考文献
附录
```

问题分析应明确每个子问的输入、决策、目标和约束，并提前说明子问之间继承的对象、公共判据或基础模型，以及新增或改变的变量、约束、目标和核心困难，使题意到模型的转化及任务依赖可追踪。若多个子问共享同一运动规律、评价指标、几何判据或状态转移，应在首次使用或公共模型处集中定义和完成必要推导；后续子问引用该基础并说明增量，只有语义或适用条件改变时才重推，避免复制公式掩盖真正差异。

任务目录用于组织材料，内容展开与完整度判断以第 4.1 节的核心主张推理链为单位；章节、公式、算法、结果和验证各自出现，不等于它们之间的论证已经成立。

### 4.1 论文完整度

论文不是 repository delivery summary；即使最终模型、公式、结果与验证均正确，也不能把理解它们如何形成所必需的推理压缩成最终答案摘要。论文写作和内容审计的工作单位是**每个核心主张的 reader-facing reasoning/evidence chain（面向读者的推理与证据链）**，不是元素是否存在。核心主张包括对题目问题的实质回答，以及决定该回答含义的模型取舍、作用机制和结论边界，不要求把每句话拆成独立主张。对具备相应基础知识、但未参与项目的第三方，正文应按实际需要连接：本题对象与问题为何导向当前建模选择，本题结构为何导向所选求解方法、算法阶段或候选排除，关键假设、约束和中间机制如何产生结果，实际证据为何支持该判断，以及结论的适用边界。这是连贯论证的读法，不是要求每个主张填写同一套栏目；只有“采用某模型”“得到某数值”“检验通过”而关键连接仍需读者自行补全，不能判为完整。

**minimal 约束冗余模型、重复证据和装饰性内容，不约束真实核心推理所需的解释深度。** 简单主张可能由短推导或一段解释闭合；复杂的耦合、取舍、候选排除或反直觉结果可能需要多个相连步骤和证据视角。展开程度由理解该主张实际需要的推理决定，不按各题统一深度，不设页数、字数、段落数或图表数量目标。禁止用通用背景、重复结论、装饰性模型或算法、无决策价值的敏感性分析及版式放大来 padding。

首次起草时就沿各核心主张回看已有 analysis、Accepted Decisions、search/optimization records、sensitivity、audits 和 frozen results，回收能帮助第三方理解的模型形成依据、关键中间量或机制、候选与算法形成过程、被淘汰路线实际改变的判断、参数响应、结果比较和可信边界，再按当前主张选择正文解释与证据视图，并按第 6.1 节检查可从已接受模型和冻结结果确定性派生、但尚未呈现的解释；不要等用户指出内容或图表不足才回收，也不要把已有一句理由视为回收完成。判断 content-complete 前，结合当前稿完成这一回看：区分“缺少支撑证据”“证据已存在但关键关系尚未进入正文”“文字已有而图表仍有独立理解或核查价值”。前者需收窄主张或补足必要分析，后两者需完成相应解释或视图，不能仅因公式、结果和验证均已出现就停止。此回看融入起草与现有内容审计，不另设阶段、清单或记录。材料各守其权威边界：分析和审计提供推理与实验背景，Accepted Decisions 控制当前语义，正式数值由 frozen results 支撑。历史推理须先核对是否仍适用于当前语义和方案，不能机械恢复旧段落或把内部 Governance、Decision Proposal、实验流水账搬入正文。

content-complete 不等于“没有明显缺项”：审计应沿核心主张顺读现有论证，检查第三方是否仍须自行补出核心模型选择、方案形成、中间机制或证据到结论的关键连接，再回到相关材料修复整条受影响的链。补写之后重新顺读这条链，判断新段落是否真正解释了前因后果，而不是以“缺项已出现”结束。图表、公式和相邻章节可以共同承担解释，不必重复陈述；若已有材料仍不足以支撑主张，说明证据不足或收窄主张，必要时返回相应分析，不能用更长文字制造支持。

完成声明须与审计范围一致：只有本次范围内的核心主张均有可理解、可核查且边界明确的推理链，才可称该范围内容充分。局部回归恢复或数值一致性检查只证明所检查的问题，不自动升级为整篇 content complete；整篇完整度审计需覆盖各子问的核心主张及其关键依赖。已经闭合的链不为扩写重做，尚有关键跳步的链也不因“已补最小一段”停止。这直接用于起草、修订和审计，不另建主张台账、checklist artifact 或审批 gate。

### 4.2 摘要

摘要不是正文压缩版，而是独立的信息入口。

应让未阅读正文的评委快速获得：

- 问题对象和核心矛盾；
- 各主要子问题采用的方法；
- 关键定量结果；
- 结论适用范围。

对于天然具有独立任务结构的题目，可按任务组织摘要；对于高度耦合的问题，不强制机械分段。

摘要中的创新、优势、推广性等表述必须对应正文已有证据，不得为了增强竞争性添加包装性描述。

### 4.3 结果与结论

结果段先报告直接证据，再解释其含义，并说明关键数值或方案为何由当前模型产生，例如哪些约束起作用、变量如何配合、空间或时间关系如何形成、候选为何被排除。解释深度以理解结论所需为限，不逐项复述参数。显著性、因果关系、最优性、鲁棒性等词必须与实际证据强度一致。候选筛选、插值、启发式和样本外比较分别按其真实地位描述，不用“全局最优”“严格证明”等更强措辞替代。

小型有限候选集若声称精确最优，应优先展示完整候选证据；若结论表现为零效应，应展示受影响集合、被删除集合与最优集合的关系，而不只报告最优值未变。

模型评价只总结正文已经展示的能力、适用条件和局限，并指向相应证据或失效机制；不把采用某算法、公式较多或程序能够运行本身写成优点，也不以“精度仍可提高”“易陷入局部最优”等通用句式代替本题真实边界。

### 4.4 附录

附录只保留理解模型、求解方法或关键证据所必需，且放入正文会妨碍阅读的内容。完整源码、测试、构建命令、仓库路径和过程记录留在项目交付物中；只有赛事明确要求或读者确实需要时，才在论文中提供复现入口。支撑材料说明应面向评阅者，交代材料支撑正文哪一部分及其证据边界，不用脚本名、机器文件清单或源码全文替代这种对应关系。

## 5. 写作语体

正文应具体、自然、由本题证据驱动。若环境已配置专门的“去 AI 味”写作 Skill，润色时优先调用该 Skill；本手册只保留以下底线：

- 少用可替换到任何论文里的套话、机械过渡和泛化评价，直接写本题对象、变量、数据、因果关系与限制。
- 不为“完整感”机械堆小标题、列表、三段式或优缺点模板；真实存在结构时再使用。
- 若删掉一句话后事实、推理或边界没有损失，通常应删掉或改得更具体。
- 去 AI 味不能牺牲严谨性；不得为了“像人写”故意加入语病、口语化、情绪化表达，或改变数字、模型名、结论方向和引文事实。
- 公式出现前先说明现实含义；结果优先报告可核验的数值与机制，不用“显著提升”“具有重要意义”等空评价代替证据。

## 6. 图与表

### 6.1 证据视角与表达形式

初稿阶段即按第 4.1 节回收的证据选择视图，不等最终结果汇总或 DOCX 排版时才配图。同时检查 accepted/frozen model 与已有结果能否确定性派生出直接可核查的中间量、机制或对照视图；尚未保存成图或单独数据文件，不等于没有可用证据。若非显然关系主要靠多个公式、表格或长文字才能在脑中重建，应主动考虑这种视图是否显著降低理解与核查成本，而非默认文字已存在就无需图表。非显然的模型形成、物理/几何机制、搜索候选、参数响应、局部失配和对照关系都可能需要图表，但不是每题必备图种。图表应承担推理链中需要展示的关系，不能仅凭图表已存在就认定主张已解释充分。先问“读者需要看到什么才能理解或核查这条结论”，再根据证据选择表格、图或文字：精确数值和有限候选集通常适合表格，空间关系、变化趋势或作用机制通常适合图，简单推导、阈值和边界可由公式与文字直接说明。

依据核心主张需要读者理解或核查的关系确定证据视角，而不是按图表类别补齐要素。公式和文字已经说清，不自动构成省略图表的理由：若图能让读者直接看见空间关系、对照差异、变化趋势或临界结构，减少自行重建关系和跨表核对的负担，就具有独立的解释或核查价值。是否增加图表取决于它能否实质改善这些理解或核查任务；不设跨项目固定图表数量，也不把少图本身当作简洁的成果。

同一组数据可以由不同载体承担互补任务：表格提供精确参数和数值，图展示关系、结构和变化，正文解释这些证据为何支持结论。需要避免的是同一关系的无效重复，而不是禁止同源数据同时出现在图与表中。图应放在实际使用它的推导、方法或结果附近，图中对象与正文符号、分组和条件相互对应，不只在最后汇总答案时配图。

按图实际支持的主张选择来源：正式方案与结果图读取对应 frozen 结果；历史机制或反例图读取明确版本的动作与条件，并核对其与当前判据的关系；搜索、候选比较和数值细化图读取真实实验记录。图注与邻近正文交代当前方案、历史实例或条件切片的身份；参数切片注明固定与变化的量及是否重新优化，避免把历史动作或条件对照画成正式方案。可沿已接受模型和冻结参数确定性计算绘图所需的中间响应、几何关系、分量或对照量；它们是条件模型的派生解释，不是新增观测、独立验证或未记录的历史轨迹，不因此重新优化或改变正式结果。实现中的来源定位和必要身份核对留在现有绘图脚本，不另建图表 authority 清单。

常见匹配：

- 空间分布/连接关系 → 地图或网络图；
- 几何构型、判据分支或坐标变换 → 与推导相互指认的示意图；
- 时间/连续参数响应 → 折线或响应曲线，可配置信带；
- 多节点差异与不确定性 → 点区间图/森林图；
- 组成结构 → 堆叠条形图；
- 数值分辨率或迭代稳定性 → 对照表或收敛图，并明确它只支撑相应的稳定性/停止判断；
- 算法阶段、分解关系或非显然分支 → 流程图；线性复述正文步骤时不画；
- 精确数值比较 → 表格通常比装饰性图更好。

对非显然的机制和判据，按理解需要选择三维构型、投影或截面等视角，并可在共同坐标和条件下并列有效/无效、单独/联合、近似/完整等有实质差异的情形，使读者看见判据排除了什么、机制新增了什么。二维投影或示意图不能被当作未经证明的三维充分判据；采样覆盖图也不能替代连续覆盖证明。

整体图承担全局配置，局部放大展示整体尺度下难以辨认的短缺口、窄窗口、临界接触或小幅差异。当正文结论依赖这些结构时，增加有明确定位和单位的局部面板，或改用更合适的尺度。绝对曲线几乎重合但差值重要时，使用差值或区间视图，而不是强行夸大纵轴差异。若已有参数响应、候选比较或数值细化证据能解释方案形成与可信范围，应考虑将其关系可视化，不只画最终参数和总值。

图型所暗示的证据强度须与实际数据一致：网格细化差异不标为严格误差界；搜索阶段结果不伪装成缺失的逐代收敛历史，也不由曲线变平推出全局最优。标准竞赛/建模工作流不假定存在同题参考作品，也不把寻找范文作为 content-completeness 方法；首次起草的推理与证据综合、content-complete 判断必须能仅依靠本项目自己的 authority 和 evidence 完成。只有在赛后复盘、教学/作业场景，或用户明确提供并允许使用外部参考材料时，才可在项目资源边界内将其用于额外的 exposition / evidence-role audit。外部参考只能帮助发现表达方式或证据视角；本项目主张仍须由自身权威材料和证据支撑，不以参考作品作为主张的证据，不导入其模型、算法、参数、数值、结论或证据强度，也不以其篇幅、图表数量或获奖等级为目标。

### 6.2 科研图视觉基线

图表风格从真实成图判断，不以技能名称、色卡或检查项齐全替代审美。当用户要求参考案例或实际项目暴露风格问题时，可针对性检索科研可视化 skill 与图库，打开少量相关案例，提炼字体、颜色角色、面板比例和标注方式；统计逻辑不匹配时只借风格。先用一至两张真实数据代表图解决视觉方向，再批量生成并逐张检查。不为探索模板扩充框架，也不机械复刻历史项目图型。

实现时可复用 [科研图选型与样式指南](scientific-figure-guidance.md) 和 `shared.figure_style`：主张与绘图必要性 → 按关系和数据结构匹配模板 → 核对转换 → 颜色语义 → 最终尺寸下的样式/布局 → 来源与跨工具视觉 QA。精确样式起点读取现有 paper profile；按项目需要覆盖，不强制迁移已认可图表。指南补充常见图型的证据边界和可运行回归示例，不另建图表清单或交付关卡。

按最终 Word 插入尺寸设计，避免生成后大幅缩小。Matplotlib 导出使用 `shared.figure_style.save_figure`；其他后端由项目生图入口执行，并按同一 profile 检查实际文件尺寸、格式与最低 DPI。格式按消费者需要选择，不能用截图倍率代替有效字号检查。默认纯色填充、实线和无点标记；冗余识别优先通过直接标签、固定分组位置或分面，有含义的虚线或事件符号显式指定，不机械添加点和斜线纹理。检查灰度时发现的问题按实际输出需求解决，不以加满纹理代替设计。图注承担统计口径、样本量、CI 类型等信息，图内只保留必要标签。

分类配色默认采用已由用户在 A/B 实际图上认可的 Paul Tol Bright 原始七色，色值与来源统一维护在 `shared.figure_style` 及科研图指南中。这是分类色起点，不是每图使用七色或固定两色的要求；按对象角色取色，连续量仍使用适合的顺序/发散色带。

本仓库新绘或修订图不采用蓝橙配色；使用共享 palette 或按项目设计其他组合，不由此自动重绘已认可的历史图。颜色先表达语义和阅读重点：同一比较任务中的对象保持一致编码，背景或参考信息适度弱化，关键对照仍须清晰可辨。类别、连续大小、相对有意义基准的正负偏离分别选择适合的分类、顺序或发散色带；不把低饱和度、某组流行色或固定色数当作学术感标准。减少“AI味”靠对象层级和论证重点清楚，不靠装饰渐变、阴影、无意义高亮或刻意避开某种默认颜色。

多面板按读者需要核对的关系组织，不机械套用相同网格。直接比较的面板尽量对齐条件顺序、单位和尺度；若尺度不同或条件不适用，应明确呈现，避免同一行看似对应、实际含义不同。先通过共享标签、简短分组标题或直接标注减少重复图例与长标签造成的查找成本，再考虑缩小字号；机制图的关系/方向、结果图的观测/预测及敏感性图的基准/变化条件应能被直接辨认，不要求每题画齐这些图种。

最终尺寸下检查数据区与文字区的比例：增加DPI不能挽救被长标签挤窄的绘图区或过细的线。网格、边框与注释按读数需要保留并控制视觉重量，不机械全删；关键小差异的尺度处理沿用§6.1，不能为美观隐藏失配。

上述表达原则可参考 [Rougier的图形设计章节](https://github.com/rougier/scientific-visualization-book/blob/master/rst/rules.rst)、[K-Dense科学可视化指导](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-visualization/references/publication_guidelines.md)；[SciencePlots图库](https://github.com/garrettj403/SciencePlots/wiki/Gallery)用于比较样式效果。它们是可选方法参考，不是本题证据或竞赛格式要求；不引入其固定期刊尺寸、强制manifest/检查清单或默认格式组合，也不据此替换项目数据与图形内容。

### 6.3 表格

列宽按语义分配。文本说明通常左对齐，方案/数值列居中或按小数点组织。先调整列宽、单元格边距和措辞，再缩小字号。

人工在 Word/WPS 中已经审核通过的表格，其布局优先于通用表格规则。内容未变时尽量保留其完整布局；内容变化时重新审核，不用旧表的布局锁定掩盖新内容问题。

## 7. Markdown、Word 与排版

论文内容与版式分阶段处理：`paper.md` 是正文内容权威；用户审核通过的 `paper.docx` 是人工版式权威。DOCX 排版工具不得静默改写已批准正文，反之 Word 手工版式也不能重新定义模型或数值证据。

AI 正常负责到 DOCX candidate 及其结构/渲染 QA。当既定交付流程要求用户在 Word/WPS 中作最终内容与视觉验收时，最终 PDF 由用户在验收后从 approved DOCX 手动导出。未经认可的 PDF 不作为版式权威或最终提交物；除非用户明确要求，不主动生成 publication PDF。

`paper/` 是 publication interface，默认只保留当前 `paper.md`、`paper.docx`，以及用户明确加入项目的最终 `paper.pdf`。conversion manifest、build statistics、document validation、visual QA 等过程产物默认输出到 stdout 或临时目录；工具要求生成 manifest 不等于需要长期提交，运行时需要的记录在临时 QA 路径生成并消费。仅有明确、持续的 downstream consumer 才保留相应过程文件，不能以文件已存在或需要证明检查过为由保留；terminal cleanup 同时移除 `paper/` 中失去当前消费者的过程产物。

没有题面、官方等 authoritative requirement 或用户明确要求时，不主动创建声明、提交表、AI-use disclosure 或相应模板。即使存在要求，也只有用户明确请求协助时才创建文件，其中具体使用事实须由用户提供或确认。

精确字体、字号、行距、页边距、页码和普通三线表等跨项目机器配置统一读取 `personal-paper-profile.yaml`，不要在 playbook、项目脚本或测试中复制数值。官方规范、用户提供的当届模板或用户批准的 Word 基线对其所属版式范围具有更高优先级。

共享 profile 顶部的名称、版本、作用域和优先级用于标识与权限解释；其余字段只保留实际被工具读取的参数。排版建议直接写在本节，不伪装成已自动执行的布尔开关。通用工具保留正文已有章、节编号，不按示例重新编号；论文标题与短表格字段尽量单行，先调整语义列宽和单元格留白，再考虑经确认的文字精简，缩小字号放在最后。算法表的说明列可按内容左对齐，不按表号硬编码布局。

明确题注优先使用 Word 的 Table Caption / Image Caption（或带图表编号的 Caption）样式，普通正文引用使用 Body Text。没有明确样式时只对紧邻图表的独立标签作推断；已知 Pandoc 转换链可先识别其 Body Text 中的相邻标签。裸文本与图表相邻仍可能存在歧义，应在源文结构或样式中明确身份。格式器规范题注间隔并检查表上图下、紧邻关系与重复编号；错位只报错定位，不自动移动内容。位置规则直接实现为校验，不再保留无人读取的位置配置。

六项基础格式由排版代码设置，并在保存后检查字体、字号、对齐、缩进、行距、段距及题注加粗。正文强调可保留，表头沿用加粗；列表、关键词、公式和参考文献按各自语义处理缩进，不强行套正文。字体归一化由共享实现负责，数学使用原生公式；复合上下标应保持正确结构，引用上标和星号、百分号、指数写法按正文数学语义检查，不声称仅凭配置已校验。Markdown 保持可编辑正文源，图宽和引用写法由实际转换与审阅核对，不默认生成 GitHub 派生预览。

采用共享 profile 的 Markdown → DOCX 生成链，若转换器未直接调用共享格式模块，先对候选执行 `python shared/paper_format.py <input.docx> --output <output.docx> --overwrite --normalize-pandoc-headings`，再进行渲染审查。该显式参数只用于已知的 Pandoc 生成链；普通 DOCX 不启用。已有人工认可的项目版式沿用 §7.2，不为套用共享默认值全量覆盖。机械格式项的自动校验入口与覆盖范围见[仓库验证入口](../../README.md#检查与运行环境)。

存在真实提交截止时间时，以当届官方要求或用户明确的交付约定核对截止时间与时区，并为内容与人工版式验收、导出、打包和上传预留失败重试余量。若导出链尚未验证且临近截止失败会危及交付，可提前用临时小样检查实际需要的公式、图表、字体和文件打开；小样只验证工具链，不使用未验收正文生成正式 DOCX candidate，不提前建立 publication PDF，也不替代 §7.1 的内容验收。改进前保留当前已满足提交要求的版本，用现有 Git 和候选输出隔离变更；剩余时间不足以完成受影响复查并恢复可提交版本时，停止可选改进。探针用后清理，只有仍需恢复的执行信息才记入已有 state；平台提交成功以平台回执或用户确认为准。

### 7.1 Markdown → DOCX

优先保持单一可编辑 Markdown 正文源。公式使用稳定的 Pandoc 数学语法，输出后检查 OMML 结构；图片路径、题注、交叉引用和表格应以最终 DOCX 的实际结果为准，而不是只看 Markdown 预览。

内容修改先回到 Markdown；内容已审核后再进入 DOCX 装配。本节的内容验收可由 AI 在用户授权范围内完成；用户明确保留的审查节点仍须等待用户结论，模型语义变更与人工 DOCX 认可分别遵守既有决策和人工验收边界。若排版阶段发现真实内容问题，退回内容源修正，而不是直接在自动生成链中偷偷改文字。构建入口默认把候选写到临时目录或显式输出路径；打包只复制现有交付，不隐式触发构建。已认可文件不因运行打包或检查命令被新候选覆盖。

正文或实际引用的图表改变后，旧 DOCX 即为 stale，不能继续代表当前内容；依赖失效不等于触发重建。figure/content 迭代阶段只同步正文、图表及必要状态，保留旧 DOCX，不自动进入装配或 Word/render QA。新的 DOCX candidate 只在当前正文与图表内容验收完成并正式进入交付排版阶段，或用户明确要求时生成；后续迭代使其再次 stale 时同样适用。若进入该阶段的工具链需要 manifest，在临时 QA 路径更新并消费；确有持续消费者的既有记录，区分可更新的当前文件定位与不可伪造的历史生成命令、时间和输入身份。核验器未追踪的图片依赖仍需直接核对。只有路径变化且正文、嵌入内容和输出字节未变时，修正当前定位并核验即可，不为迁移重写已批准的 DOCX，也不刷新历史生成时间。

进入 DOCX 装配时，有效的内容验收包含第 4.1 节对已有证据及其正文表达的回看，不仅是公式、数值与边界无误。若当前 `paper.md` 版本已有这样的内容验收，直接沿用该结论，不为排版重复回收；若验收后正文发生实质修改，只复查受影响的核心主张及其关联摘要和结论。只有当前版本缺乏有效内容审查、且不能通过上述局部复查更新已有验收时，才补做完整的 4.1 和 4.2 内容验收。转换成功、数值检查通过或旧版本的“正文已完成”状态，均不能替代当前版本有效的内容验收。生成后的 DOCX 先作为 candidate，结构检查和自动渲染通过只说明相应检查项未发现问题；在用户要求人工视觉验收的场景中，只有收到明确验收结论后才可将其记为人工版式权威或 frozen。

### 7.2 人工 Word 基线

用户在 Word/WPS 中明确调整并认可的版式是后续布局工作的基线，接受结论属于当时的具体内容与输出版本。优先提取或局部复用已批准结构，不反复凭感觉猜行距、列宽或分页参数；内容或版式变化后按影响范围复查，不能把旧版视觉接受直接转授给新候选。

对锁定表格、公式、分页等局部对象，必要时采用针对性的 OOXML 修改，避免全量重写文档导致无关布局漂移。任何自动处理后的 DOCX 都应结合结构检查和实际渲染检查受影响页面。

### 7.3 视觉 QA

结构检查回答“对象是什么、属于哪里”；实际 Word/WPS 或逐页渲染回答“页面上看起来怎样”。二者不能互相替代。

重点检查：公式缺字/竖排、正文意外居中、表头孤立、表格换行与列宽、图片裁切、题注绑定、参考文献、附录和异常大片空白。开发阶段只复验受影响页面；完整逐页检查留到正式交付。

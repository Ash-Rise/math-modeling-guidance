# 十分钟体验：食堂备餐

这个示例使用合成需求情景，演示一次计算、查看结果、改变条件和换对话接续。只需 Python 3.11—3.13 标准库，无需外部附件、账号、模型下载或 pip 安装。实际设置时间取决于你的环境。

先读 [教学题目](problem-statement.md)。题面已经规定损失函数、等权情景和并列处理；本例不再创建重复的决策记录。

## 运行默认方案

可以请 AI 按本页运行，或在仓库根目录执行：

```shell
python projects/quickstart-canteen/run.py
```

若你的系统使用 python3 命令，请让 AI 检查实际解释器后替换。脚本根据自身位置定位数据，也可以在其他工作目录运行。

结果保存在本项目的 `results/baseline/`：`report.md` 是可以直接阅读的短报告，`summary.json` 保存参数、输入快照和数值，`candidates.csv` 包含全部 141 个候选。重新运行同一标签会更新该目录内的这三个生成文件；人工修改请另存。

## 做一次条件比较

题目第二个情景将缺餐损失由每份 9 元降为 3 元：

```shell
python projects/quickstart-canteen/run.py --shortage-cost 3 --label lower-shortage
```

新结果保存在 `results/lower-shortage/`，不会替换默认方案。改变默认参数却仍使用 baseline 标签时脚本会报错，提醒你为比较方案另起名字。

随仓库提供的结果可用于核对运行是否成功：

| 情景 | 推荐备餐量（份） | 情景平均损失（元） | 平均剩餐（份） | 平均缺餐（份） |
|---|---:|---:|---:|---:|
| 默认：缺餐损失 9 元/份 | 110 | 48.00 | 11.50 | 1.50 |
| 对比：缺餐损失 3 元/份 | 100 | 30.00 | 5.00 | 5.00 |

缺餐代价较高时，方案倾向多备餐以减少缺餐；代价对称时，本例的中位数 100 份最优。这是该情景模型的解释，不是现实经营建议。

让 AI 对比两个报告，解释推荐量和平均剩餐、缺餐怎样变化。注意两个情景的损失函数不同，不能把两者损失之差称为同一目标下的算法改进。

## 暂停并从新对话继续

运行默认方案后，先对 AI 说：

> 请保存默认结果，在这个项目的 state.md 记录尚未做缺餐损失为 3 元的比较及下一步命令。核对输入、代码、结果和状态都能进入本地版本，然后保存检查点。告诉我文件保存和 Git 提交是否都成功，不推送远端。

再打开同一工作区的新对话：

> 请读取 AGENTS.md，恢复 projects/quickstart-canteen。根据教学题目和 state.md 完成剩余比较，保留默认结果，说明两个情景各自的结论和局限。

状态只记录尚未完成的工作，已经完成比较就不要再记录“待比较”。所有任务结束后按仓库规则清理失去恢复用途的状态。脚本本身不操作 Git，也不会自动创建状态文件；这些动作由你或 AI 完成。
